Notes on unsupported rules in native transformers

The deduplication-with-conflict-detection logic (drop the entire order_id group if any rows conflict) is not expressible in the built-in remove_duplicate transformer, which only keeps/drops by key equality. It is encoded in the LLM node's Python instruction instead. All other rules are likewise implemented there because they form a tightly coupled validation chain; splitting them across multiple standard nodes would break the "drop row on any field failure" interdependency.
